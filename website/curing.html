Curing Engine

Achaea combat runs on afflictions — negative status effects that stack up and have to be cured with the right herb, salve, elixir, or action before they compound into something worse. Emunah's curing engine tracks what's afflicting you and queues the right cure automatically, once per game tick, one cure per resource in flight at a time.

Vectors and per-vector priority

A vector is a resource that gates a cure. Eating a herb, applying a salve, smoking a pipe, sipping an elixir, and focusing your mind all draw on separate balances in Achaea — you can do all of them in the same second. Two herbs, on the other hand, cannot happen at once; eating uses up the one "herb" balance regardless of which herb it is.

This is the single most important design decision in the engine: there is no global priority list. If there were, the most urgent affliction would hog the tick even while waiting on salve balance, and three herb cures that could have gone out simultaneously in that same second would wait behind it. Achaea combat is decided largely on that throughput. So each vector is resolved independently, against its own ranking, every tick:

herb
salve
smoke
elixir
focus
tree

Six cures can be in flight simultaneously — one per vector — each fighting for its own balance, not anyone else's.

The affliction table

src/emunah/curing/afflist.lua holds 117 afflictions, each with:

  • one or more cure options, in preference order — a vector, an item, its Alchemist mineral equivalent, and (for salves) a body location
  • a priority per vector: an integer rank, 1 = most urgent for that vector specifically
paralysis = {
   cures    = { { vector = "herb", item = "bloodroot", alt = "magnesium" } },
   priority = { herb = 6 },
},

anorexia = {
   cures    = { { vector = "salve", item = "epidermal", alt = "sensory", location = "body" },
                { vector = "focus" } },
   priority = { salve = 1, focus = 2 },
},

alt is the Alchemist mineral equivalent, used automatically when curing.method is set to minerals instead of herbs — the herb ↔ mineral mapping lives in exactly one place per entry.

Blocking afflictions — the classic lock

Three afflictions each shut down an entire vector, and each is cured by a vector one of the other two blocks:

AfflictionBlocksCured by
anorexiaeating (herb)apply epidermal, or FOCUS
slicknessapplying (salve)smoke valerian, or eat bloodroot
asthmasmoking (smoke)eat kelp

With all three up, every item vector is shut and FOCUS is the only way out — which is exactly why focus ranks anorexia second in its own priority list. The engine consults this table before ever queuing a cure, so it won't queue eat kelp while anorexic and then sit there wondering why nothing is happening.

How a tick resolves

Once per game prompt (Char.Vitals, which Achaea sends every time), the engine runs through this sequence:

  1. Reconcile tracked afflictions against the server's own list (periodically, not every tick — see Detection for what "reconcile" means here).
  2. Writhes first. Bound, webbed, roped, and similar movement-locks aren't cured by items — the cure is repeated WRITHE, and while active most other actions are refused anyway, so this always goes first, unconditionally.
  3. Healing. Not an affliction, but it outranks everything on the vectors it uses — there is no value in curing stupidity at 8% health. See Healing below.
  4. For each vector independently (herb, salve, smoke, elixir, focus, tree): pick the lowest-ranked tracked affliction that vector can cure, confirm you can actually perform that cure right now (item on hand, defence not blocking it, mana available for focus, a lit pipe for smoking), and queue the command.
  5. Flush the queue — send at most one command per vector that's actually free right now.

The capability gate

A resolved cure still has to pass have.cure() before it's queued: is the item actually in inventory or the Rift, is the vector currently blocked by another affliction, is there mana for FOCUS, is a pipe loaded for smoking. This is the layer that keeps the engine from confidently sending a cure command for an item you ran out of three fights ago.

Healing

Four healing sources draw on three independent balances, so most of them do not compete with each other and several can be in flight simultaneously. Each has its own threshold, and the defaults descend so that cheaper, renewable sources engage before finite ones.

SourceBalanceSettingDefault
drink manaSipcuring.manaThreshold85%
drink healthSipcuring.healthThreshold80%
eat iridMosscuring.iridThreshold68%
perform handsEquilibriumcuring.handsThreshold50%

Health and mana are the exception: both are elixirs and share one sip balance, so they compete, and health always takes priority. Irid moss restores both bars on a balance nothing else uses. perform hands spends equilibrium, which makes it the one healing source that competes with attacking.

A command the game cannot perform still costs time

Asking for a fluid no vial contains produces What is it that you wish to drink? — nothing is drunk and no balance is spent, but the send still occupies the elixir vector until its confirmation times out. Because health and mana share that vector, an impossible mana sip repeated on a loop stops health sipping entirely. Emunah frees the vector on that reply and stops requesting the fluid for two minutes, logging what needs refilling.

Rift management

Curatives live in the Rift and must be withdrawn before they can be used, and OUTR has a round trip — withdrawing a herb at the moment an affliction lands produces a cure that arrives too late. Emunah keeps three of each curative in inventory, withdrawing one item at a time as stock falls.

The ceiling matters as much as the floor. Inventory is lost on death and the Rift is not, so anything above the target is risk carried for no benefit; surplus is returned automatically. Stock is checked when inventory is listed rather than only on a prompt, so a reload restores correct levels immediately rather than at the next combat round.

Defence keep-up

A second, much simpler system restores defences that have dropped, using the same action queue as curing so the two never fight over a balance. It's simpler because Char.Defences is genuinely complete — the game tells you exactly which defences you have, always. No trigger layer, no reconciliation, no ambiguity. Compare that to afflictions, below.

Keep-up always runs at a fixed low priority — any cure outranks it. And it defers entirely while the engine is tracking any affliction: re-raising a defence mid-lock usually just gets it stripped again immediately, so it waits until you're clear. 

emunah defs add rebounding
emunah defs on

Detection: GMCP and triggers

This is the part worth understanding before trusting the engine in a real fight, especially PvP.

Affliction state comes from two independent sources:

SourceReliability
GMCP (Char.Afflictions) Reliable, but reports only what Achaea chooses to announce. Complete enough for PvE bashing. Incomplete in PvP — being afflicted with things you weren't told about is often the entire point of an opponent's strategy.
Triggers (game text) The way to close that gap — parsing Achaea's own affliction messages as they scroll past, which is what every mature curing system relies on for PvP.
Why the shipped trigger set is small on purpose

Achaea's ~200 affliction onset messages aren't published anywhere transcribable. Writing patterns for all of them from memory or guesswork would produce a table that looks complete and is quietly wrong in places — and a wrong pattern is strictly worse than a missing one. It asserts an affliction you don't actually have, and the engine burns a real balance curing something that isn't there, in the middle of a fight, for a reason invisible in any log.

So the shipped corpus (src/emunah/curing/detect/patterns.lua) contains only patterns that are structurally certain — Achaea's own rejection messages ("You are afflicted with anorexia and cannot eat anything."), which are stable, generic, and say exactly what's wrong. Everything else grows from evidence, not assumption.

Growing the corpus from evidence

emunah learn on     # log candidate lines while you fight
# ... fight, or spar in the arena ...
emunah learn off
emunah detect        # coverage report

emunah learn on logs lines matching Achaea's typical affliction-message shape ("You ..." / "Your ...", short, present tense) to emunah-learn.txt. After the fight, read the file, and add exactly what you saw: 

detect.define("paralysis", {
   gain = { [[^Your muscles seize up completely\.$]] },
   cure = { [[^Your muscles unlock and you can move again\.$]] },
})

A gain pattern asserts the affliction the moment it's seen. A cure pattern retracts it and immediately confirms whichever vector was waiting on it — without that, the vector stays blocked until a fallback timer lapses, which costs roughly a full extra cure's worth of time per affliction. Patterns are always anchored with ^ and $; an unanchored pattern will match the same words quoted back at you in a tell.

How the two sources reconcile

GMCP is authoritative for removing a tracked affliction — if the server's list no longer mentions it, it's gone. But addition only ever corroborates: an affliction detected by a trigger survives even when GMCP hasn't (yet, or ever) reported it, because in PvP it frequently won't. This asymmetry is what lets trigger-detected state actually mean something instead of being overwritten by an incomplete server list every reconcile pass.

How the cure data is verified

The affliction/cure mappings, herb↔mineral equivalents, salve locations, and — critically — the per-vector priority ordering are checked against Achaea's own A Lesson in Herbs, and independently cross-checked a second time against Achaea's official help pages and a second affliction dictionary (documented in full in the repo's docs/afflictions.md, including a handful of flagged discrepancies still awaiting in-game verification).
