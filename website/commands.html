Command Reference

Everything runs through one alias: emunah <subcommand> [argument] [rest]. This is deliberate — Achaea already has a large command vocabulary of its own, and one entry point means emunah with no arguments can list everything the system can do. 

emunah              # the full command list
emunah status       # system and character state

Most subcommands with no argument print a status report instead of doing anything — reading state is always safe to try.

General

emunah

Prints the full command list. Also what runs if you type emunah with no arguments at all — the closest thing to documentation most people will ever read, so it's kept accurate.

emunah status

One-screen overview: character name, class, whether curing/defence-keepup/UI are on, cure method (herbs or minerals), how many afflictions are currently tracked, how many skills are indexed, inventory item count, and the current log level.

emreload

Reloads every module from disk — the core development loop. Re-reads the loader file itself, not just the modules it already knows about, so a newly-added file takes effect immediately. See how this differs from a plain reload.

Curing

emunah cure on|off  (shorthand: ec)

Toggles the curing engine. ec alone is the fastest way to flip it mid-fight. Starts off on a fresh install — never auto-enabled.

emunah affs

Lists every currently-tracked affliction: its known cure vectors, where it came from (gmcp or trigger), and how long it's been active. Prints clear when nothing is tracked.

emunah prio <affliction> <vector> <rank>

Override a built-in cure priority without editing afflist.lua. Lower rank = more urgent. Stored in your per-profile config and checked ahead of the shipped table.

emunah prio paralysis herb 1
emunah learn on|off

Logs candidate affliction messages (lines matching "You/Your ..." while you fight) to emunah-learn.txt in your Mudlet home directory. The workflow for growing the detection corpus — see Detection.

emunah detect

Reports detection pattern coverage: how many known afflictions have a gain pattern, how many have a cure pattern, out of the total known. GMCP covers the rest.

Defences

emunah defs on|off

Toggles defence keep-up: automatically restores any defence on your wanted list that drops. Always runs at a lower priority than curing — a defence raised mid-lock is worth doing, never at the cost of a cure.

emunah defs add <defence>  /  emunah defs remove <defence>

Add or drop a defence from the wanted list.

emunah defs add rebounding
emunah defs remove rebounding
emunah defs list  (or bare emunah defs)

Shows every wanted defence and whether it's currently up or missing.

Combat — PvE

emunah bash on|off

Starts or stops the bashing loop on its own, without moving between rooms. Requires a loaded class module (auto-detected on login).

emunah bash attack <command>

Override the attack command sent (target replica number is appended automatically). Defaults to smite.

emunah bash balance eq|bal|both

What the attack costs — equilibrium, balance, or both. Verified from what the class actually uses, not assumed.

emunah bash health <n>

Stop bashing below this percentage of health (default 50).

emunah hunt [off]

The walker and the bashing loop together — walks the area and kills things, moving on once each room is clear. emunah hunt off stops both.

emunah mobs here|target|done|reset|add|skip|kill|forget|areas

Manage the per-area denizen kill list.

  • here — what's in the room right now, by replica number (always target the number, never the name)
  • target — pick the next thing to kill
  • done — mark the current target dealt with
  • reset — clear the dealt-with list for this room
  • add <name> / forget <name> — record or remove a denizen from this area's list
  • skip <name> / kill <name> — keep it recorded but off (or back on) the kill list
  • areas — every area with recorded denizens

With no argument: everything recorded for the current area, kill counts, and what's here right now.

emunah loot on|off|now

Automatic gold pickup from corpses. now sweeps the current room immediately.

Combat — PvP

emunah pvp on|off

Starts or stops the PvP loop. Mutually exclusive with bashing in both directions — starting one stops the other automatically.

emunah pvp target <name>  /  emunah pvp target off

The only way a target is ever set — there is no auto-acquisition. See why.

emunah pvp target sarapis
emunah pvp target off
emunah pvp  (no argument)

Status: running state, class module, current target and their tracked afflictions (if any), attacks sent, and who's in the room.

Movement

emunah walk start|stop|pause|resume|move|avoid <id>|unavoid <id>|auto on|off|delay <s>|return

Controls the area walker directly (usually driven through hunt instead).

  • start — explore the current area room by room
  • pause / resume — hold in place without losing progress
  • move — take one step immediately
  • avoid <id> / unavoid <id> — exclude or re-include a room
  • auto off — stop self-pacing; a consumer (like the bashing loop) drives timing instead
  • delay <seconds> — how long to wait after a room change before stepping again

No argument: area, rooms remaining/visited/unreachable, who's pacing it, auto-step state.

emunah keys on|off

Numpad movement bindings, bound for both Num Lock states (a numpad key sends the digit with Num Lock on and the navigation key with it off — both are bound so the pad never silently stops working). Pressing a movement key stops the walker.

7 nw    8 n     9 ne
4 w     5 look  6 e
1 sw    2 s     3 se
0 in    . out   + up   - down

Interface

emunah ui [rebuild|reset|show]

Bare emunah ui toggles the interface. rebuild tears it down and rebuilds from scratch; reset clears saved layout state for a panel stuck off-screen or hidden; show forces it on.

emunah ui map [height <n>|on|off|centre|rebuild|float|embed|raw]

Bare emunah ui map runs a full diagnostic rather than toggling anything (deliberately — the natural thing to type when the map looks broken is this exact command, and if it toggled the map off that would look like confirmation something's wrong). Reports whether Geyser and the Mapper widget exist, whether the map database actually has room data, current geometry, and more.

  • height <n> — percentage of window height, clamped 10–70%
  • centre — center the view on the current room
  • float / embed — detach into its own dock widget, or embed in the main window
  • raw — call createMapper directly, bypassing Geyser (a decisive test for isolating a Geyser-layer bug from a data-layer one)

Configuration

emunah set [key] [value]

Generic settings get/set, dotted-path addressed.

  • emunah set — dump every setting
  • emunah set curing.method — read one setting
  • emunah set curing.method minerals — write one (booleans and numbers are coerced automatically)
emunah set bashing.stopBelowHealth 60
emunah set curing.confirmWait 1.5
emunah set curing.method minerals

Settings persist per Mudlet profile in emunah-config.lua.

Diagnostics

emunah have [thing]

With an argument: an ad-hoc lookup answering exactly what the curing engine asks — is this a known skill, is it in inventory, is it in the Rift, is the matching defence up.

emunah have kelp

With no argument: a full capability report — every cure vector's state (ready / recovering / blocked by <affliction>), skills-indexed status, inventory and Rift counts.

emunah gmcp [refresh]

Dumps everything Emunah currently tracks from GMCP. refresh requests a full resync from the game.

emunah debug handlers|timers|queue

Internals: handlers lists every registered event handler by owner (useful for confirming reload didn't leak anything), timers lists active timers, queue snapshots the cure action queue.

emunah debug

With no argument, toggles verbose logging — which includes every command the system sends to the game, printed as -> smite 19316 before it goes out.

This is the tool for “why did it do that?”. It also shows commands that were held rather than sent, with the reason (stunned, prone, no balance) — so a system that is deliberately waiting is distinguishable from one that has hung.

emunah debug gmcp

Traces every GMCP message sent and received, with its payload summarised to one line:

[gmcp] << Char.Items.List {location="room" items=[4]}
[gmcp] >> Char.Items.Room
[gmcp] << Room.Info {num=6181 name="North gate" exits={...}}

Its own switch rather than part of emunah debug, because Char.Vitals arrives with every prompt and would bury whatever you turned debug on to see.

Received messages are traced even when the handler ignores the payload — “it arrived and we ignored it” and “it never arrived” look identical from the outside, and telling them apart is usually the whole question. Arrays show their length (items=[4]), which is what distinguishes an empty room from a list that never came.
