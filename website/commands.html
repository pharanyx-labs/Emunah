Command Reference

Ninety-four commands across five areas. Every one of them is also in the client itself — type emhelp.

The prefix

Everything runs through one dispatcher, under two names: 

emset status      # the short form -- what you type, and what this page uses
emunah status     # the long form -- identical; what reads best in a script

A single entry point rather than a scatter of top-level aliases, for two reasons: Achaea has a large command vocabulary of its own and colliding with it is easy, and one entry point means bare emset can list everything the system does.

There is no longer a ! prefix

! used to be a second universal prefix meaning exactly what emunah means. It has been removed, not deprecated — ! now falls through to the game untouched, and the test suite asserts that it does.

Two spellings for every command meant everything documenting one had to pick a side, and they picked differently: the in-game help said !, this website said emunah, and the README said both in different tables. Settling on one is what lets emhelp state a single syntax per command.

A handful of commands additionally have a bare form, with no prefix at all — pp, emdefs, ndb, pipes, manna, affpop, emhelp, emreload and sleep. Those are the ones typed mid-fight, where a few extra keystrokes is the difference between using the command and not bothering. They are marked below.

This page is generated from the data the client uses

src/emunah/help.lua holds the command reference as a table, and emhelp renders it in Mudlet. This page is rendered from that same table, so it cannot describe a command the client does not have. The test suite asserts the other direction: every handler, every bare alias and every shipped setting must appear in it, or lua test/run.lua fails.

emhelp

The reference, in the client, where you need it. 

emhelp                     # the index
emhelp curing              # one topic
emhelp bash                # every bash command
emhelp defs                # every defence command
emhelp search gold         # find a command by what it does
emhelp settings            # every setting, with its current value
emhelp settings curing     # ...for one topic, with explanations
emhelp keys                # the key bindings
emhelp all                 # everything

Every line printed is clickable, so the index, a topic, a command and its cross-references are all one click from each other. emhelp keeps its own name rather than living under the prefix, because it is the one command you type before you know what the prefix is.

Settings

Read and written with emset set: 

emset set                            # dump the whole table
emset set curing.confirmWait         # read one
emset set curing.healthThreshold 75  # write one, and save it

There are seventy-eight documented keys. Thirty-six ship in the defaults file; the rest are read with a fallback at their use site and can be set, but will not appear in the config file until you do. emhelp settings lists both, marks which is which, and marks any value that differs from its default.

Core

State, settings, reloading and diagnostics.

emset

Bare form: emset

the short list -- the ten commands a normal session uses

Bare emset, with no subcommand. This used to print the full forty-line reference, which is a lot to hand someone who typed nothing but the prefix. emhelp has everything.

emunah <command>

the long form of the same prefix

Every command in this reference is written emset ..., because that is what you type. emunah ... is the identical dispatcher under its full name, and is what appears in comments, log lines and scripts, where the extra letters read better than they type. emset status and emunah status are the same command. There used to be a ! prefix as well; it has been removed rather than deprecated, and now falls through to the game untouched.

emset status
emset bash on
emhelp

Bare form: emhelp

this help system -- index, topics, per-command cards, search

With no argument, the index. With a topic name, that topic's commands. With a command, the full card for it: syntax, arguments, examples, the settings it touches and what they are set to right now. Everything printed is clickable.

ArgumentMeaning
<topic>one of the categories listed by the index
<command>any command, with or without the emunah/emset prefix
emhelp
emhelp curing
emhelp bash
emhelp search gold
emhelp search <word>

find every command mentioning a word

Matches across syntax, summary, detail text and setting names, so searching for what you want to DO usually finds it even when you do not know what the command is called.

emhelp search gold
emhelp search balance
emhelp settings [topic|key]

every setting, its default, and what it is right now

Includes the keys that are settable but not in the shipped defaults -- there are more of those than there are shipped ones, and none of them were documented anywhere before this. A value differing from its default is marked.

emhelp settings
emhelp settings curing
emhelp settings bashing.attack
emhelp keys

the numpad and function-key bindings

Read from keys.lua's own tables rather than transcribed, so it cannot disagree with what is actually bound.

emhelp all

every command in every topic, in one page

For reading through, or for searching with Mudlet's own buffer search.

emset help

the same index as emhelp

Kept because it is what the system has always answered to, and because emset help reads better in a script than emhelp does.

emset status

system and character state on one screen

Version, character, class, whether curing and keep-up and the interface are running, the cure method, how many afflictions are tracked, how many skills and inventory items are indexed, the log level, and the three safety floors -- which are shown in red when set to zero, because a disabled floor looks identical to a low one until it kills you.

Settings: curing.enabled, defences.enabled, ui.enabled, curing.method, logLevel, bashing.stopBelowHealth, pvp.stopBelowHealth, watch.critical

emset set

dump the whole configuration table

The raw table. emhelp settings is the readable version, with defaults and explanations.

emset set <key>

read one setting

Prints (unset) when the key has never been written, which is different from a key set to its default.

ArgumentMeaning
<key>a dotted path, e.g. curing.confirmWait
emset set curing.confirmWait
emset set <key> <value>

write one setting, and save it

true, false and numbers are coerced; everything else is stored as a string. Written straight to disk, so it survives a reload and a restart.

ArgumentMeaning
<key>a dotted path -- see emhelp settings for all of them
<value>true, false, a number, or text
emset set curing.healthThreshold 75
emset set bashing.attack "angel sear"
emset reload

re-read every module from disk

Re-executes the bootstrap, so a newly ADDED module is picked up too -- re-requiring the existing manifest silently would not see it.

emreload

Bare form: emreload

the same reload, as one word

Owned by the loader rather than commands.lua, so it still works when commands.lua is the module that failed to compile.

emset debug

toggle verbose logging -- every command sent, and every command held

The single most useful thing to turn on before reporting a problem. The held lines are the valuable half: they say why the system decided NOT to act, which is invisible otherwise and is usually the actual complaint.

Settings: logLevel

emset debug gmcp

trace GMCP traffic in and out

Off by default and separately toggled, because it is a lot of output. This is what to paste when the question is what the game actually said.

emset debug handlers|timers|queue

internals: registered handlers, live timers, the action queue

queue is the one to reach for when something is not being sent: it shows what is pending on each vector and what is in flight awaiting confirmation.

emset gmcp [refresh]

tracked GMCP state, or ask the game to resend it

refresh re-requests inventory, rift and skills. Useful after a desync, and the first thing to try when a cure is refused for something you are holding.

emset have [thing]

capability report, or check one item or skill

With no argument: how many skills and items are indexed, how many rift entries, and for each cure vector whether it is ready, recovering, or blocked by an affliction. With an argument: whether that is a skill you have, an item in inventory, an entry in the rift, or a defence currently up.

ArgumentMeaning
[thing]a skill name, item name or defence name
emset have
emset have bloodroot
emset have rebounding
emset chat [rebuild]

chat capture vs rendering -- which half is working

Capture and rendering are separate modules and fail independently. "Chat stopped" has three different causes -- the game stopped sending, the console broke, or no console was ever built -- and this tells them apart in one line.

Settings: ui.chatTabs

emset chyron <text> | clear

queue an announcement on the scrolling strip at the top

Up to three messages scroll on a loop. The manual entry point to the same call anything else in the codebase would make programmatically.

ArgumentMeaning
<text>what to scroll
cleardrop everything queued
emset chyron Anzerloi is in the arena
emset chyron clear
emset ui [rebuild|reset|show]

toggle, rebuild or reset the interface

With no argument, toggles the whole interface off and on. rebuild recreates the containers, reset discards saved geometry, show un-hides them -- which is the one to try if the interface has gone invisible.

Settings: ui.enabled

emset ui map [on|off|centre|rebuild|float|embed|raw|height <n>]

the map: status, size, or where it lives

With no argument it REPORTS and never toggles -- deliberately, because the map has about eight ways to be broken and the report distinguishes them. float detaches it into its own dock; raw bypasses Geyser entirely.

ArgumentMeaning
height <n>percent of the window, 10-70

Settings: ui.map, ui.mapHeight, ui.mapFloat

Curing & defences

The affliction engine, defence keep-up, and detection.

pp

Bare form: pp

pause or resume curing AND defence keep-up together

Both, as one action, on purpose. A cure engine paused while keep-up carries on raising defences is not the fight paused, it is half paused -- and the half still running is the half that spends balances. Resuming is defined as "either one is currently off", so one press always lands on a clean state.

Settings: curing.enabled, defences.enabled

emset cure on|off

the curing engine alone

Off by default. Curing is opt-in because a system that starts eating herbs the moment it loads is not something to hand someone unannounced.

Settings: curing.enabled

emset affs

tracked afflictions, their cure vectors, source and age

Shows why an affliction is NOT being cured when that is the case -- the refusal reason, or "no cure defined". Prints a red warning inside the list when curing is switched off, rather than only in the header.

emdefs

Bare form: emdefs

the clickable defence grid

Three states per defence, not two, and that is the point of building a grid rather than printing a list. [ ] off, [o] defup (raise it once if it is missing), [x] keepup (raise it whenever it is missing), [-] we hold no command capable of raising it at all. The NAME is coloured by what is actually true right now: green up, red wanted but down, dim down. A defence sitting wanted-but-unraisable looks identical to one that is merely down, and stays that way forever, which is why the fourth state exists.

Settings: defences.keepup, defences.commands

emset defs on|off

defence keep-up as a whole

Settings: defences.enabled

emset defs list

wanted defences, with mode and whether each is up

done (lapsed) means a defup-mode defence was raised once and has since fallen; that is expected, not a fault.

emset defs add <name> [command]

want a defence, optionally supplying how to raise it

The second form is for defences we have no command for -- tattoos, mostly. Without it, a defence can be wanted and unraisable, which the grid shows as [-].

ArgumentMeaning
<name>a Char.Defences name -- see emset defs names
[command]what raises it, e.g. touch boar
emset defs add rebounding
emset defs add insomnia touch moss

Settings: defences.commands

emset defs mode <name> defup|keepup|off

how hard to try for one defence

defup raises it once if missing and then leaves it alone. keepup raises it whenever it is missing, indefinitely. off stops wanting it.

ArgumentMeaning
<name>a Char.Defences name
emset defs mode rebounding keepup
emset defs mode speed defup

Settings: defences.keepup

emset defs names

every name Char.Defences uses, and whether we can raise it

The names the game uses and the names people type diverge more than they should -- a defence is usually known by whatever grants it, and the game names it after what it does. venom is the elixir; poisonresist is the defence.

emset defs remove <name>

stop wanting a defence (drop also works)

ArgumentMeaning
<name>a defence currently on the wanted list
emset prio <aff> <vector> <rank>

override a cure priority

Lower ranks are cured first. Per-vector, because the right order to eat herbs in is not the right order to apply salves in.

ArgumentMeaning
<aff>an affliction name
<vector>herb, salve, elixir, smoke, focus, tree, writhe or special
<rank>a number; lower is cured sooner
emset prio paralysis herb 1

Settings: priorities

emset detect

detection pattern coverage

How many afflictions are known, how many have gain patterns, how many have cure patterns. The gap between the first and the second is the honest measure of how much of the corpus is written.

emset learn on|off

log candidate affliction messages to a file

For building the pattern corpus: records lines that arrived alongside an affliction change, so a real message can be lifted verbatim rather than guessed at.

affpop [on|off]

Bare form: affpop

walk AFFLICTION LIST and AFFLICTION SHOW into a corpus file

Sends AFFLICTION LIST, answers the MORE prompts itself, then AFFLICTION SHOW for every name it found. One command, several hundred round trips -- run it somewhere quiet.

Combat & movement

Bashing, hunting, the area walker, kill lists and PvP.

emset bash on|off

the combat loop

Attacks whatever is targeted, retargets when something dies, and stops when health falls below the floor. Does NOT move on its own -- emset hunt is the version that walks.

Settings: bashing.attack, bashing.stopBelowHealth, bashing.soloOnly

emset bash

the session report

Attack, costs, target and its health, an estimate of the kill, how many killed, damage dealt and taken, rooms cleared, and how fresh the room's item list is -- that last one being the usual reason a loop looks stuck.

emset bash attack <command>

what to attack with

One matched pair of surrounding quotes is stripped, so a multi-word attack can be given either way.

emset bash attack angel sear
emset bash attack "angel sear"

Settings: bashing.attack

emset bash balance eq|bal|both

what the attack REQUIRES before it can be sent

Settings: bashing.balance

emset bash consumes eq|bal

what the attack SPENDS when it lands

A distinct axis from balance, and getting them confused is why an attack loop stalls: Angel Sear requires both but consumes equilibrium, so a system watching balance for its recovery waits for a signal that never comes.

Settings: bashing.consumes

emset bash health <n>

stop attacking below this percentage of health

Zero disables the floor, and emset status shows it in red when it is zero.

ArgumentMeaning
<n>percent, 0-100

Settings: bashing.stopBelowHealth

emset hunt [off]

walk the area AND kill things

Starts the walker first and then the bashing loop, in that order deliberately: the reverse attacks whatever is in the room before the walker has decided where it is.

emset walk start|stop|pause|resume

the area walker on its own, with no fighting

Settings: walker.auto, walker.stepDelay

emset walk

walker report: area, rooms remaining, visited, unreachable, avoided

"Paced by" is the useful field -- it says what the walker is currently waiting on, which is usually the answer to why it has stopped.

emset walk move|next

take exactly one step

For when auto-stepping is off, or for stepping through a route by hand to see where it goes wrong.

emset walk avoid <id> | unavoid <id>

never route through a room, or stop avoiding it

ArgumentMeaning
<id>a room number, as shown by emset walk and the room panel

Settings: walker.avoid

emset walk auto [off]

step automatically, or only on request

Anything that is not the literal word off turns it on.

Settings: walker.auto

emset walk delay <seconds>

seconds between steps, 0.1 to 30

Settings: walker.stepDelay

emset walk return

toggle returning to the starting room when finished

Session-only -- this one is deliberately not persisted.

Settings: walker.returnToStart

emset mobs

denizens recorded for this area, and which are on the kill list

Settings: denizens.autoRecord

emset mobs here

what is in the room now, by replica number

Green is on the kill list, yellow is already dealt with, grey is skipped. Clickable.

emset mobs target|done|reset

target the next wanted denizen, mark the current one engaged, or clear the room

reset forgets what has been dealt with in this room, which is what to use when the loop thinks a room is clear and it is not.

emset mobs add|remove|skip|kill <name>

edit the per-area kill list

skip keeps the denizen recorded but off the list -- different from remove, which forgets it and lets auto-recording add it back.

ArgumentMeaning
<name>a denizen name as the game writes it
emset mobs areas

every area with recorded denizens

emset pvp on|off

the PvP loop

NEVER auto-targets. A system that picks its own target in a player fight is one mis-parse away from attacking an ally, so the target is always explicit.

Settings: pvp.stopBelowHealth, pvp.verses

emset pvp target <name> | target off

who to fight

Refuses a name recorded as an ally, and refuses your own.

ArgumentMeaning
<name>a player name
emset pvp attack <n>

how many afflictions to stack before switching to damage

ArgumentMeaning
<n>a count

Settings: pvp.attackAtAfflictions

emset keys [on|off|rebuild]

numpad movement bindings

rebuild re-binds everything, which is the fix for "enabled but nothing is bound" -- a state the report will tell you about explicitly.

Settings: keys.numpad

sleep

Bare form: sleep

SLEEP, and record that you meant it

The one place this system deliberately shadows an Achaea verb, because the collision IS the mechanism. Being asleep is otherwise indistinguishable from an opponent having put you there -- same affliction, same GMCP payload, same blocked state -- and the only evidence that a sleep was wanted is that you asked for it a moment earlier. The command still goes to the game; this records intent, it does not replace the verb. Anchored to a bare SLEEP: sleep with an argument is a different command and passes straight through.

Shop, loot & sustenance

Buying, picking up gold, pipes and the manna rite.

emset shop [proprietor]

redraw the last WARES seen -- clickable, buys by replica number

Grouped by category. Clicking an item buys it. The listing is whatever the game last showed, so this is a redraw rather than a fresh query.

ArgumentMeaning
[proprietor]a named shop, when more than one has been seen

Settings: shop.stowIn

emset shop spent

gold spent this session, itemised

Verified against Char.Status rather than assumed from what was sent -- a purchase that was refused should not appear in the ledger.

emset shop limit <gp> | off

hold back any single purchase over <gp>

A click is one keystroke away from a very expensive mistake in a shop that lists by replica number.

ArgumentMeaning
<gp>gold, or off to clear the limit

Settings: shop.confirmAbove

emset loot [on|off|now]

pick up gold from corpses

now sweeps once regardless of the setting. By default it only lifts gold when alone and from kills it believes are ours.

Settings: loot.gold, loot.aloneOnly, loot.ownKillsOnly, loot.noDenizens, loot.stowIn

pipes [on|off]

Bare form: pipes

keep the pipes filled and lit

The smoke cure vector needs a lit pipe with the right herb in it, and nothing else maintains that. Without this, smoke cures are refused for a reason that looks like a missing herb.

Settings: pipes.enabled, pipes.assign, pipes.poll

emset pipes now

check the pipes immediately rather than on the next poll

manna

Bare form: manna

the sustenance rite: perform, get bowl, drink bowl

Three commands with real waits between them. One word because it is a thing you do several times a day and the sequence is fiddly to type.

People

The name database, dossiers, standing and highlighting.

ndb

Bare form: ndb

the roster

ndb works bare, without the emunah prefix, deliberately: the database is consulted mid-fight about a name that just walked in, and five extra keystrokes at that moment is the difference between looking someone up and not bothering.

ndb ally|enemy|neutral|dragons|marks|infamous

filtered rosters

ndb city|house|order|class <name>

everyone recorded with that affiliation

ndb city Mhaldor
ndb class Serpent
ndb here

who is in the room, with what we know about them

Unknowns are shown with a ? and "not recorded" rather than omitted -- that someone is present and unrecorded is itself worth seeing.

ndb show <person>

the full dossier (who and whois also work)

ArgumentMeaning
<person>a name
emset whois <person>

the dossier on one person

Falls back to the Achaea web API when the name is not recorded, so this answers for anyone, not only people already seen.

ArgumentMeaning
<person>a name

Settings: namedb.autoFetch

ndb stats

coverage: standing, cities, and what is still unknown

The gaps are the point -- how many records have no city, no class -- because that is what says whether the database is worth trusting yet.

ndb fields

the settable field schema

ndb set <person> <field> <value>

record a fact by hand

ArgumentMeaning
<field>one of the names from ndb fields
ndb set Malefactor city Mhaldor
ndb note <person> <text>

attach a free-text note

ndb unnote <person> [index]

drop one note, or all of them

With no index, every note on that person goes.

emset iff <person> ally|enemy|auto

declare a standing -- declaration beats derivation

auto hands the decision back to the derived rules (city, house and order hostility). An explicit declaration always wins, and survives an import.

ArgumentMeaning
<person>a name
ndb hostile [off] <kind> <org>

treat a whole city, house or order as hostile

ArgumentMeaning
<kind>city, house or order
ndb hostile city Mhaldor
ndb hostile off city Mhaldor
ndb capture [on|off]

which listings are being read, and what each is waiting for

Names are learned from CW, CLWHO, QW, HONOURS and the guardian angel. The report says which of those have produced anything, which is how you tell "not implemented" from "never seen one".

Settings: namedb.capture

ndb api [on|off]

the Achaea web API: transport, queue, cache, hits and misses

Requests are serialised and cached (six hours for a hit, twenty-four for a miss) because the endpoint sends no rate-limit headers and it seemed unwise to find the limit experimentally.

Settings: namedb.autoFetch

ndb refresh [<person>|all]

re-fetch one person, or everybody, one per second

ndb online

who is online now, split into known and new

ndb learn

record and enrich everyone currently online

The fastest way to go from an empty database to a useful one.

ndb prune [days]

drop records that are only a name

Anything declared, noted, or given a single fact by hand survives, so this can never quietly discard judgement.

ArgumentMeaning
[days]also require the last sighting to be this old
ndb forget <person> | forget all

delete one record, or the whole database

forget all confirms twice and names the count at stake, with a fifteen-second window on the confirmation.

ndb export [fields <a,b,c>] [path]

write the database out, optionally as a field subset

Notes are excluded from a field-subset export, since those are yours.

ndb import <path>

merge somebody else's database into yours

Additive. Their file is evidence about people you have not met, not a correction of judgement you have already recorded -- so your own iff and your own notes survive intact.

ndb path

where the database is stored, and how many records it holds

emset names [on|off]

highlight known names in the game text

With no argument, prints the legend: what each colour and weight means. Colour answers "where do they stand relative to me"; weight answers "is there something notable about this person". They stack, and each is independently readable.

Settings: names.enabled

emset names ignore <person> | unignore <person>

keep one name out of the highlighter

For the ally whose name is a common word, or the shopkeeper you see forty times an hour. Forgets nothing else about them.

emset names tint on|off

tint neutral names by city

Settings: names.cityTint
