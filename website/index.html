Emunah

A client-side automation system for Achaea on Mudlet. It tracks the game's GMCP state, renders it, determines what the character can do at any moment, and drives curing, hunting and movement from that state.

Overview

Emunah runs inside Mudlet alongside the game. It consumes everything Achaea reports over GMCP — vitals, afflictions, defences, inventory, room contents, skills — maintains a normalised model of that state, and acts on it in three areas:

Interface

Vitals strip, affliction and defence panels, tabbed chat, room and target panels, and an embedded map. Built from Geyser widgets, and entirely optional.

Curing engine

Tracks affliction state and resolves one cure per resource per tick — eating, applying, smoking, sipping or focusing — while handling the afflictions that block a whole vector.

Movement and combat

Walks an area room by room, engages authorised denizens, collects loot and advances. PvP targeting exists but is never auto-acquired.

Development model

The module tree lives on disk as plain Lua in a git checkout rather than bundled inside a Mudlet package. Editing a file and typing emreload rebuilds the entire system from disk — no package reimport, no client restart. The reload-safety problems that model introduces, and how each is handled, are documented in Architecture.

Scope of affliction detection

Affliction state comes from Char.Afflictions, which is reliable but reports only what Achaea chooses to announce. That is sufficient for hunting and incomplete for player combat, where being afflicted without notification is the point. See detection for how the gap is closed from observed evidence rather than assumption.
