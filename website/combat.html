Combat & PvP

Three layers work together: an area walker that explores room by room, a bashing loop that finds and kills denizens as it goes, and a PvP module for targeting a specific player — deliberately kept separate from bashing rather than bolted onto it.

The area walker

Event-driven and self-paced by default — it steps on its own after arriving somewhere, using Mudlet's own map data, no separate mapper script required.

Two pacing modes: auto (its own timer decides when to step next) or claimed by a consumer — the bashing loop claims it the moment a fight starts, so its own attack cadence controls movement instead of the walker's timer marching you out of a room mid-fight. 

emunah walk start
emunah walk avoid 4521    # skip a specific room
emunah walk auto off      # hand pacing to a consumer instead

Targeting by replica number

Achaea rooms routinely have two of the same creature — "a pixie" and "a pixie" aren't the same pixie, and typing smite pixie lets Achaea pick which one, whose choice shifts as they move and die. Every targeting decision in Emunah goes by replica number instead — the unique instance id GMCP reports for each item in the room — never by name.

denizens.lua separates two ideas that are easy to conflate: a durable per-area kill list (which kinds of creature to bother with here, persisted across sessions) and a live per-room target (which specific instance, by id, is being fought right now). 

emunah mobs here      # what's in the room, by replica number
emunah mobs skip rat  # keep it recorded, but stop killing it
emunah mobs areas     # every area with a recorded kill list

The hunting loop

Closes the loop between the three pieces above:

walker arrives
→
pick a denizen
→
attack while possible
→
it dies
→
next, or move on

A kill is detected by the creature leaving the room's item list — not by parsing a death message, which varies by creature and by class. This is deliberately more robust than it sounds: it also catches the creature fleeing, being killed by someone else, or being dragged away, all of which mean the same thing to the loop — stop attacking it, pick another.

Room-clear detection is guarded carefully: a freshly-entered room's item list hasn't arrived yet, and mistaking "no data yet" for "genuinely empty" would send the walker marching through an entire area attacking nothing. The loop only declares a room clear once it's confirmed the current room's contents have actually arrived.

Safety

An unattended loop that can't stop itself is how a character gets fed to a denizen. The bashing loop halts on:

  • health below a configurable threshold (emunah bash health <n>, default 50%)
  • too many failed attacks on one target (default 40) — gives up and moves on rather than grinding forever on something unkillable by this attack
  • the class module refusing to attack (no balance, or an unhandled shield)
  • a player arriving, if bashing.stopOnPlayer is set — bashing is built to avoid PvP, not stumble into it (see PvP for the actual PvP path)
  • the walk finishing — an exhausted route ends the hunt rather than leaving the loop ticking over nothing
  • disconnect, or a manual movement key
Stepping, not speedwalking

The nearest room still to be walked can be several steps away, and a speedwalk crosses the whole route in one go — marking every room it passes through as visited without ever announcing an arrival. A hunt would then path straight past rooms full of denizens.

So while bashing is pacing the walker it moves one room at a time, which is what claiming the walker was always for. A plain emunah walk with nothing looking for a fight still speedwalks.

Never in front of anyone

While bashing is running it will not attack at all with another player in the room, and it leaves rather than waiting for them to go — standing still doing nothing is its own kind of conspicuous, and waiting would deadlock the walk anyway.

Separate from bashing.stopOnPlayer, which ends the session outright. This just refuses to swing. Gold pickup follows the same rule, and additionally only takes what fell from something you killed yourself. Both are on by default (bashing.soloOnly, loot.aloneOnly, loot.ownKillsOnly).

Knocked down, stunned, off balance

A denizen's charge attack can stun and knock down in one hit, and Achaea refuses commands during either — every command while stunned, and anything needing you upright while prone. A loop that keeps attacking through that produces a wall of rejections and nothing else.

Both states are tracked from the game's own messages, and the attack is gated on them through core/act.lua (see Architecture). Standing back up is sent once per knockdown rather than once per rejection, and is held until the stun lifts, since STAND is refused while stunned like everything else.

Seeing what it decided

emunah debug prints every command before it goes out, and every command that was held along with why (stunned, prone, no balance) — so a loop that is deliberately waiting is distinguishable from one that has hung. 

emunah hunt          # walk + bash together
emunah bash health 60
emunah hunt off

Loot

Automatic gold pickup, same replica-number discipline as targeting — a specific pile, not "gold" in general, so it can't grab the same pile twice or the wrong one when several are on the floor.

emunah loot on
emunah loot now   # sweep the current room immediately

Class support

Offence is behind a small adapter interface with a plugin contract: the rest of the system calls into a class module, never the other way around, so a class can be swapped without touching the bashing loop, the walker, or PvP. 

attack(target)      -- send the primary attack
canAttack()         -- balance/resource check before attacking
handleShield(t)      -- how this class breaks a shielded target
onTick(vitals)       -- per-prompt hook for class resources
stats()              -- named class resources for the UI

The class is auto-detected from Char.Status (or a skillset fallback) the moment you log in — nothing to configure. Priest is the only class implemented today: sends smite <replica>, costs balance (verified in play, not assumed — the balance requirement is a setting rather than hardcoded, since a second attack might cost something different). Adding another class means filling in this same five-function shape; nothing else in the system needs to change. See the Roadmap for which class is planned next and why.

PvP

Explicit opt-in, always

emunah pvp target <name> is the only way a target is ever set. There is no auto-acquisition, on purpose.

Room.Players — the GMCP feed of who's in the room — is documented by Achaea's own protocol behaviour as incomplete: anyone concealed (shrouded, hiding, phased) generates no entry at all. A targeting loop built on "whoever's in the room" would happily forget an opponent the moment they conceal, or worse, engage the wrong person automatically. In PvP, guessing wrong is a much worse failure than doing nothing, so the PvP module never guesses — a target is a name you typed, full stop. 

emunah pvp target sarapis
emunah pvp on
emunah pvp             # status: target, their tracked afflictions, attacks sent
emunah pvp target off

Mutually exclusive with bashing

A denizen and a player cannot be fought on the same balance. Starting PvP stops an active hunting session, and starting a hunt stops an active PvP session, automatically in both directions.

Opponent affliction tracking

GMCP reports only the character's own afflictions, never an opponent's. Tracking an opponent's state therefore uses the same mechanism that closes the PvP detection gap: third-person trigger patterns grown from observed combat via emunah learn on, following the workflow in Curing → Detection.

One structural difference: there is no server-confirmed signal that an opponent's affliction has been cured, as there is for the character's own. Entries therefore age out on a timer rather than being reconciled away — see src/emunah/curing/detect/opponent.lua. The module ships with no patterns, the same starting state the self-detection corpus began in.

See Architecture for how these modules fit into the module tree, or the Roadmap for what's planned for PvP offence next.
