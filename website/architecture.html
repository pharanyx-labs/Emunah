Architecture

Emunah lives on disk as a plain Lua module tree, loaded into Mudlet by a small bootstrap package rather than being bundled inside one. This page covers the module layout, the reload model that makes edit-and-go possible, the bugs fixed along the way, and where the design is structured the way it is.

Module layout

src/emunah.lua bootstrap loader (manifest + reload) src/emunah/ core/ util log event config timers queue act gmcp/ init vitals status afflictions defences items skills room comm ire have/ capabilities -- the "can I actually do this" gate curing/ afflist curelist engine defkeepup detect/ (init, patterns, opponent) ui/ theme layout vitals affpanel chat roompanel map walker.lua -- area walker keys.lua -- numpad movement bindings denizens.lua -- per-area kill list, targets by replica number bashing.lua -- walk -> target -> attack -> next -> move loop pvp.lua -- PvP loop, opt-in target only loot.lua -- pick up gold by replica number class/ adapter priest -- interface + auto-detection commands.lua test/ mock_mudlet.lua run.lua -- 470+ behavioural tests package/ .mpackage build project tools/ build-xml.py syntax_check.py run_tests.py

The load order in src/emunah.lua's manifest is explicit, not alphabetical — later modules index earlier ones at load time (UI reads the theme, curing reads the affliction table), so order matters and is spelled out rather than inferred.

One gate for every command

Achaea refuses commands for reasons that have nothing to do with the command itself: you are stunned, you are lying down, the balance it costs has not come back. Those rules used to live at each call site — bashing had its own copy, the curing queue had another, loot had a third. Every newly discovered rule then had to be added in three places, and whichever one was missed carried on firing into rejections once per prompt.

core/act.lua is now the single place that knows them. Call sites declare what a command costs, never when it is allowed: 

emunah.act.send("smite " .. target, { standing = true, bal = true })
emunah.act.send("get " .. id,       { standing = true })
emunah.act.send("stand")

Two distinctions in there are load-bearing, and both were learned the hard way:

  • Stun is not a declarable requirement. It blocks literally every command, so it is checked for all of them regardless of what they ask for.
  • Prone is not blanket. An earlier version blocked curing while knocked down too. That is both wrong — herbs and elixirs work fine lying down — and dangerous: being knocked flat in a fight is precisely when refusing to heal gets you killed. Only actions that genuinely need you upright declare standing.

The one deliberate bypass is keys.lua. A command you typed goes straight out — you asked for it, and second-guessing a human is how a system feels broken.

Sent is not executed

The subtlest balance bug in the system had nothing to do with gating. Achaea processes a command some time after it arrives, and until it does, Char.Vitals goes on reporting the balance that command is about to spend as available — truthfully. Two attacks would go out on consecutive prompts, both while the game's own prompt read ex-, and the second collected “You must regain balance first.” when the first finally landed.

A flag GMCP is entitled to overwrite cannot defend against that. The guard is a timer, armed the moment a command leaves and re-armed with the exact figure when the game confirms execution and states its cost (Balance used: 3.2s.).

How long that first, pre-confirmation guard should be is measurable rather than guessable: it covers exactly one send → response round trip, which is what Mudlet's getNetworkLatency() reports. A fixed guess is wrong in both directions — on a fast connection it throws away most of a balance, on a bad one it is not enough — so it is sized from the real figure with slack for jitter, and clamped so a wild reading can neither wedge the loop nor disable the guard.

Movement costs balance too

Achaea volunteers a room's contents before the Room.Info saying you have arrived. Mid-speedwalk, that means the tracked room contents already describe the room in front of you — so the bashing loop would acquire a target it had not reached yet and attack it in transit. Confirmed live: a smite sent from a room containing nothing but a signpost, at a pig standing in the room after it.

Because movement also costs balance, that stray attack then raced the mapper's next step for the same balance, and one of them collected “You must regain balance first.” The fix is to ask the walker whether it is between rooms rather than infer it from GMCP message ordering — the walker knows, and message order only hints.

The reload model

Extend package.path to point at the checkout, invalidate package.loaded for every module, require them in order, restore package.path. The whole namespace is rebuilt from scratch on every reload — no stale module tables linger, because nothing survives except a short explicit list (event handler registry, timers, aliases, and a small scratch space modules use to persist settings across a reload).

Why emreload re-executes the loader file itself

A naive reload would call the same in-memory load() function every time — but that function closes over the manifest as it existed when the loader was first read. Calling it again re-requires every module the manifest already lists, and silently ignores a module you just added to it: the new file is on disk, its manifest entry is on disk, and neither is in memory yet. The result looks like nothing happened, because everything that did reload looks up to date. emreload re-executes the loader file itself, rebuilding the manifest, the loader, and the namespace together in one pass.

Failure modes handled

Each of these is locked down by a test, not just fixed and forgotten:

Handler leaks on reload

Registering event handlers at module scope means reloading stacks a new generation on top of the old one, so after three reloads a single GMCP message gets processed three times — in a curing system, that's three cures queued for one affliction. core/event.lua tracks handler ids on a registry that survives reload and tears the previous generation down first.

pcall result assigned unconditionally

Assigning the pcall result whether or not the require succeeded installs the error string as the module — every later call into it then fails with a confusing "attempt to index a string value". Here, a failed load aborts with the offending filename and rolls the whole reload back rather than leaving a half-built namespace that looks functional.

Char.Items.Update copying the wrong item

Rebuilding an inventory entry from the existing record rather than the incoming one means updates never actually land.

findAndRemove deleting the wrong element

The ported walker logic did table.remove(t, table.index_of(t, item)); when the item is absent, index_of returns nil, and table.remove(t, nil) silently drops the last element instead — the walker quietly skips unrelated rooms. walker.lua checks before removing.

O(n²) pathfinding

The original walker pathfinds every remaining room on every move. walker.lua pre-ranks candidates by map coordinates and pathfinds only a bounded set.

Char.Vitals.bal / .eq arrive as strings

They come over GMCP as the strings "1" and "0" — and in Lua, "0" is truthy. if gmcp.Char.Vitals.bal then is true even when you have no balance. Everything routes through a single util.bool() helper instead of trusting truthiness directly.

Test discipline

test/mock_mudlet.lua is deliberately strict rather than permissive: each mocked Geyser widget class exposes only the methods the real one actually has, and MiniConsole constructor fields are validated against the legal set. This isn't fussiness — two real, shipped bugs (MiniConsole:setStyleSheet, which doesn't exist on that widget type, and a constructor field wrapWidth that Geyser silently ignores instead of erroring on) got through review specifically because an earlier, more permissive mock accepted anything passed to it. A strict mock turns "silently wrong at runtime" into "fails the test."

The same discipline extends to matching real Mudlet behaviour precisely — the mock's trigger and alias matchers translate the actual PCRE-regex subset those APIs take (not Lua patterns, which look similar but aren't the same language), including anchors, character classes, and capture groups, so a pattern that would silently never fire in real Mudlet fails a test here instead.
