Documentation / Under the hood

Architecture

Emunah is a tree of plain Lua modules loaded straight from a git checkout. Four ideas carry most of the design, and each exists because of a specific failure it closed off.

Module layout

src/emunah.lua            the loader: the manifest, loading and reloading
src/emunah/
  core/      util log event config timers queue act outgoing
  gmcp/      init vitals status afflictions defences items skills room comm ire
  have/      capabilities         -- "can I actually do this right now"
  curing/    curelist afflist deflist engine defkeepup
             detect/  init patterns opponent opponent_patterns diag
  ui/        theme gag echo alert layout chyron vitals affpanel chat roompanel map names
  namedb/    api capture          -- with namedb.lua: who everyone is
  class/     adapter priest       -- the class interface, and Priest
  walker  denizens  ih  watch  bashing  pvp     -- hunting and PvP
  loot  shop  elist  shield  antitheft  manna  pipes  riding  keys  presences
  help  commands                 -- every command, as data, and its dispatcher
test/        mock_mudlet  run  bench  profile  latency  ui_preview
tools/       build-xml  build-trigger-package  build-commands-page  run_tests  syntax_check

The load order is written out in the manifest rather than inferred, because later modules read earlier ones as they load: the interface reads the theme, curing reads the affliction table.

One gate for every command

Achaea refuses commands for reasons that have nothing to do with the command: you are stunned, lying down, entangled, or the balance it needs has not come back. Those rules once lived at each call site, and whichever copy missed a new rule went on firing into refusals once per prompt.

core/act.lua is now the only place that knows them. Every automated command declares what it needs, and the gate decides when that can be met:

emunah.act.send("perform penitence " .. target, { standing = true, eq = true })
emunah.act.send("order " .. id .. " follow me", { bal = true, eq = true })

Stun, sleep, unconsciousness and death hold everything, whatever a command declares. Prone holds only what needs you upright, so curing carries on while you are knocked down, which is exactly when it matters most.

One slot per balance

core/queue.lua is not one queue but one slot per balance. A more urgent action replaces what is waiting in its slot; a less urgent one is dropped rather than stacked, because a backlog of stale cures is worse than none. A queued action is checked again at the moment it would send, since the reason for it, or a block on it, can change while it waits.

Sent is not executed

The game runs a command some time after it arrives, and until then it goes on reporting the balance that command is about to spend as available. Two systems reading that honestly would both send, and the second would be refused.

So a balance is treated as spent from the moment something of Emunah's goes out on it until the game answers: the queue holds the slot, and any other command that needs that balance waits behind it, whatever the next GMCP update says. When the game states the cost, such as "Balance used: 3.2s.", the exact figure replaces the estimate.

The reload model

emreload pulls the latest main, then rebuilds the whole namespace from disk: every module is dropped and required again in manifest order. Only a short, explicit list survives: event handlers, timers, and a small scratch space modules use to carry state across a reload, such as which pipes are lit.

It re-executes the loader file itself rather than calling the loader already in memory. That function was built around the manifest as it was when first read, so a module just added to the manifest would otherwise be silently skipped while everything else looked up to date.

Failure modes closed off

Each of these was a real bug, and each is pinned by a test.

FailureWhat prevents it
Event handlers stacking on every reload, so one affliction queued three cures after three reloadscore/event.lua tracks handlers on a registry that outlives the reload and removes the previous generation first.
A failed module load installing its error message as the moduleA failed load aborts with the file's name and rolls the whole reload back.
Inventory updates rebuilt from the old record, so they never landedUpdates are built from the incoming record.
Removing an absent room from a list deleting the last one insteadThe walker checks before it removes.
Balance and equilibrium arriving as the strings "1" and "0", where "0" is true in LuaEvery GMCP boolean goes through one conversion.

Evidence before code

Every game mechanic Emunah relies on is recorded in docs/game/ with the transcript or GMCP trace that established it: what a command costs, what it needs, the exact text that confirms or refuses it. Where the reference system and Emunah disagree on curing or balances, the reference system wins unless a timestamped transcript shows the game has changed. A plausible guess about the game is never shipped as fact.

Testing

The suite of 2433 behavioural tests runs the real modules against test/mock_mudlet.lua, with no client involved. The mock is strict on purpose: each mocked widget has only the methods the real one has, and trigger patterns are matched as the regular expressions Mudlet actually uses. Two shipped bugs once got past a looser mock that accepted anything; a strict one turns "silently wrong in the client" into a failing test.

Every behavioural fix carries a test that would have caught the original report, and the suite must be green before anything is committed. The suite also checks the documentation against the code: every command is documented, nothing documented is missing, and the figures on this site match their sources.
