Performance

Achaea combat is decided on round trips. A cure that resolves after the prompt it was needed on is a cure that did not happen. Mudlet runs every installed package in a single Lua state on the UI thread, so time spent here is time the whole client is not drawing, not reading input, and not sending — and the garbage produced here is collected at the exact moment the character is being locked.

This page records what the hot paths are, what was wrong with them, and how to measure whether a change made things better. Everything below was measured, not reasoned about.

The two paths that matter

Only two code paths run at game speed, and they have very different costs.

PathFires onCost
Trigger matchingEvery line of game outputMudlet C++ PCRE — effectively free to us
engine.tick()Every prompt (Char.Vitals)All of it ours
The per-line path is already optimal

Every pattern in curing/detect/ is registered with tempRegexTrigger, which Mudlet matches in C++ before any Lua runs. There is no Lua handler on sysDataReceived and there must not be one: a per-line Lua callback would run for every line of a busy area's output, and that is the one budget in this system with no slack in it at all.

The per-prompt path is where the work is. curing/engine.lua's tick() reconciles affliction state, resolves a cure on each of six vectors, checks healing across three independent balances, and maintains rift stock — on every prompt, which in a fight is several times a second.

What it costs now

Measured with test/bench.lua under a realistic lock: eight afflictions tracked across every vector, herbs in hand, health and mana below all four healing thresholds.

BeforeAfter
engine.tick()1851 µs321 µs
config.get("curing.confirmWait")0.76 µs, 88 B0.13 µs, 0 B
afflist.priority(aff, vector)0.92 µs, 152 B0.49 µs, 0 B

A 5.8× reduction in the per-prompt cost, and the four queries the tick leans on hardest no longer allocate at all.

The five things that were wrong

Each of these was found by profiling, not by reading. The order is the order they mattered.

1. Re-lowercasing the entire inventory, thirty times per prompt

gmcp/items.lua matched item names case-insensitively by calling name:lower() on every entry, on every query. Restocking asks have.quantity() once per restockable consumable — eighteen of them — and have.cure() asks count() once per cure option it considers. That is dozens of full inventory scans per prompt, each rebuilding lowercase copies of strings that only change when Achaea sends a Char.Items message.

Item names are now lowercased once, in copyItem(), the only way an item enters storage. This alone was worth roughly 40% of the tick.

2. Recomputing answers that only change when the game says so

Even with the lowercase fixed, count() and quantity() still walked the pack for each of the same eighteen names every prompt. Both are now memoised against items.generation, a counter bumped by every one of the six sites that mutates M.locations.

Why the memo is dropped wholesale

The dangerous failure here is a stale count — believing the character still holds a herb it has already eaten, which has the engine queue a cure that cannot fire. Invalidation is therefore total rather than surgical, and test/run.lua asserts every edge (add, remove, update, list, and per-location isolation), each after a read has primed the cache, since that is the only ordering in which a missing invalidation shows up.

3. Formatting log messages nobody would read

log.debug(fmt, ...) built its message and then checked whether the level allowed printing it. At the default info level that is a pcall and a string.format run and discarded on every debug call — and tick(), queue.flush() and act.send() between them reach log.debug several times per prompt. The level check now comes first.

4. Allocating a table to say “nothing”

Three separate hot functions allocated a fresh {} per call:

  • config.get(path, {}) — the default table is built on every call whether used or not, and afflist.priority() did this once per tracked affliction per vector.
  • afflist.curesVia() returned a new list every call, for a table that never changes.
  • items.at() answered an unknown location with a new empty table.

All three now share read-only constants, and curesVia() builds a per-affliction index on first use — afflist.afflictions is written at load and never mutated at runtime, so the answer for a given pair cannot change.

5. Splitting the same dotted paths forever

config.get("curing.confirmWait") ran a gmatch per call, and gmatch allocates an iterator every time. The engine reads a couple of dozen settings per prompt; settings change when a human types emset set. Reads are now memoised by path, invalidated wholesale by set(), load() and reset().

Two details are load-bearing and both are tested: a cached miss must die when the path is later created, and the fallback belongs to the caller — two call sites may ask for the same missing path with different defaults, so the cache stores a sentinel rather than the first caller's default.

Measuring

lua test/bench.lua [iterations]     # wall time and bytes per call
lua test/profile.lua [iterations]   # sampling profiler, hottest lines

Two traps, both of which produced confidently wrong numbers before they were noticed:

os.clock is stubbed

mock.install() replaces it with the manually-advanced test clock so cooldown maths is deterministic. Timing against it measures the fake clock — the first version of bench.lua reported a flat “250000 µs/call” because it stepped the clock 0.25 s per iteration. Use mock.realClock.

The profiler's own timings are meaningless

debug.sethook at a 1000-instruction interval dominates the wall clock. Its relative sample counts are what to read; take absolute figures from bench.lua, which runs unhooked.

Rules for changes to the tick

  • Nothing per-line in Lua. If a new detection need arises, it is a tempRegexTrigger.
  • Cache against a generation, not a timestamp. A time-based cache in a curing system is a stale-state bug waiting for a fight to expose it. Bump a counter at the mutation site.
  • Every memo needs an invalidation test, written to prime the cache first.
  • Prefer a shared read-only constant to a fresh empty table, and never hand one to something that mutates.
  • Measure before and after. git stash push -- src/ gives an honest baseline; the benchmark files are untracked and survive the stash.
Everything on this page was measured, not reasoned about. The benchmark and profiler live in test/bench.lua and test/profile.lua; the draw-call budget is asserted in test/run.lua.
