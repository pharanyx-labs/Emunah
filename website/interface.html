Interface

In a MUD the scrolling text is the interface. Everything here is chrome, and chrome that draws the eye away from the text is actively harmful during a fight.

Layout

Three Adjustable containers — left, right and bottom — plus a thin strip along the top. The game console keeps the middle. Everything about you is on one side; everyone else (chat, the map) on the other; the combat HUD sits directly under the last line of text, above the prompt, where you are already looking.

top chyron (scrolling announcements) left everything about you, as three titled sections: room -- where, who, denizens, items afflictions -- each with its cure and what is happening to it defences -- what keep-up is owed, then what is up right chat -- the whole column map bottom combat HUD: target and status, resource gauges, balance strip
emset ui                  # toggle the whole interface
emset ui rebuild          # recreate the containers
emset ui reset            # discard saved geometry
emset ui show             # un-hide -- the fix for "it has gone invisible"

The interface used to go permanently invisible

Rebuilding hides the previous generation of containers. Adjustable.Container:new inherits hidden from a same-named container, autoSave writes it to disk, and autoLoad restores it. So after one reload the UI was built correctly and then immediately hidden, permanently, with no error anywhere.

New containers are now explicitly shown after a rebuild, and saved state that says "hidden" does not win. Both are asserted in the test suite.

Panels

PanelShows
RoomName, area, number, exits and shop/bank details; then people, denizens and items, each under a heading with a count. People are coloured by the same policy the highlighter uses. Identical items collapse to one row with a multiplier. Each denizen is clickable: a filled dot means the hunting loop will attack it, a hollow one that it will not, and a click toggles it.
AfflictionsIn curing order. Each row shows the affliction, what will cure it, and what is happening about it: curing (sent, unanswered), next (goes out on this prompt), a countdown (its balance is recovering), ✕ anorexia (locked, and by what), or the engine's own reason for refusing it ("bloodroot is in the rift, not in hand"). Above the rows, pills for any state that holds every command (stunned, asleep, prone). Below them, one line per lock: "anorexia shuts herb, sip, purgative, moss".
DefencesA two-column list: what keep-up is owed first (amber, or dim while keep-up is off), then what is up. The title bar carries the count of each.
Combat HUDRow one: the target's health bar, and pills for what is switched on (curing, keep-up, bashing, PvP and its target, rate limiting) beside the commands sent and not yet answered. Row two: health, mana, endurance and willpower, each with its percentage and its change since the last prompt. Row three: the balance strip, then XP and class stats.
Balance stripOne cell per balance: BAL and EQ, then herb, salve, sip, purgative, smoke, focus, moss and tree. Green with a tick when ready; blue with an arrow while a command on it is unanswered; grey with the seconds left while it recovers; red with a cross when an affliction or paralysis holds it; dim when there is nothing to use. It applies exactly the rules the queue does, so it can't show something as ready that the system won't send.
ChatCaptured channels, tabbed. Capture and rendering are separate modules and fail independently.

Affliction colour carries the source: server-confirmed afflictions are solid, trigger-detected ones dimmer. They have genuinely different reliability and hiding that would make a desync impossible to spot.

The chyron

A scrolling ticker in the top strip, for things that must not be missed. Up to three messages are held at once and all of them scroll continuously on a loop — the way a TV chyron actually moves, not a slideshow that pauses on each message in turn. 

lua emunah.ui.chyron.send("text")
lua emunah.ui.chyron.clear()

Anything in the codebase pushes to it with the same call.

Banners and labels

ui/echo.lua provides the one-off announcements: a boxed centred banner in the main console, a highlighted line framed by a short colour gradient, and small floating labels anchored over the game console.

The ** PAUSED ** label is the worked example. Curing and defence keep-up are both independently pausable, and a system silently doing nothing is exactly the failure mode a banner like this exists to make impossible to miss. It is persistent — no duration — and stays up for as long as either is off.

Theme

One place for every colour, font and border, so panels stay consistent and a retheme is a single-file change. A dark, low-saturation base with a small number of saturated accents reserved for information that changes: health, balance, afflictions.

Colours are given as hex strings for Qt stylesheets and as RGB triples for the echo functions, derived from the same source. Note that Geyser.MiniConsole has no setStyleSheet — that is a Label and Gauge method, and calling it on a console is a hard error. A console's background comes from the color field of its constructor instead.

What the interface costs

Mudlet runs every installed package in one Lua state on the UI thread, so a panel repaint is time the whole client is not drawing, not reading input, and not sending. Two rules, both enforced by the test suite:

  • A panel draws once per repaint, not once per row. The defence grid used to emit a separate Qt rich-text parse per cell — thirty-odd of them.
  • A panel whose rendered content is unchanged does not draw at all. A restock pulling five herbs fires five item events, none of which change what the room shows.
  • Nothing is drawn before the cure is sent. Panels paint once the packet has been handled, coalesced: two afflictions in one packet paint the panel once.
  • Countdowns tick slowly, and only while something counts. Every 0.2 s by default (emset ui.refresh, 0 to turn them off), stopping as soon as every balance is back.

lua5.1 test/ui_preview.lua out.html renders the interface from the real panel code in a scripted fight, for a look at a change without Mudlet.
