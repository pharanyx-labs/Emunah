Interface

In a MUD the scrolling text is the interface. Everything here is chrome, and chrome that draws the eye away from the text is actively harmful during a fight.

Layout

Three Adjustable containers — left, right and bottom — plus a thin strip along the top. The game console keeps the middle.

top chyron (scrolling announcements) left room + items -- above afflictions -- below right chat -- above defences grid -- below bottom vitals strip, target gauge, vector lights, class stats map
emset ui                  # toggle the whole interface
emset ui rebuild          # recreate the containers
emset ui reset            # discard saved geometry
emset ui show             # un-hide -- the fix for "it has gone invisible"

The interface used to go permanently invisible

Rebuilding hides the previous generation of containers. Adjustable.Container:new inherits hidden from a same-named container, autoSave writes it to disk, and autoLoad restores it. So after one reload the UI was built correctly and then immediately hidden, permanently, with no error anywhere.

New containers are now explicitly shown after a rebuild, and saved state that says "hidden" does not win. Both are asserted in the test suite.

Panels

PanelShows
RoomName, area, exits, shop/bank details, who is here (coloured by the same policy the highlighter uses), and the items on the floor. Creatures are clickable — a click toggles whether the hunting loop will attack that denizen.
AfflictionsOrdered by curing urgency rather than onset, annotated with the vector that will cure each. During a fight the useful question is never "what do I have", it is "what is the system about to do about it, and on which balance".
DefencesA three-column colour-coded grid. Green up, amber wanted but missing.
Vitals stripHealth, mana, endurance, willpower, XP; balance and equilibrium lights; a light per cure vector (green ready, grey recovering, red blocked by an affliction); and class stats from charstats.
ChatCaptured channels, tabbed. Capture and rendering are separate modules and fail independently, which is why emset chat reports on both halves.

Affliction colour carries the source: server-confirmed afflictions are solid, trigger-detected ones dimmer. They have genuinely different reliability and hiding that would make a desync impossible to spot.

The chyron

A scrolling ticker in the top strip, for things that must not be missed. Up to three messages are held at once and all of them scroll continuously on a loop — the way a TV chyron actually moves, not a slideshow that pauses on each message in turn. 

emset chyron <text>
emset chyron clear

Anything in the codebase can push to it programmatically; the command is the manual entry point to the same call.

Banners and labels

ui/echo.lua provides the one-off announcements: a boxed centred banner in the main console, a highlighted line framed by a short colour gradient, and small floating labels anchored over the game console.

The ** PAUSED ** label is the worked example. Curing and defence keep-up are both independently pausable, and a system silently doing nothing is exactly the failure mode a banner like this exists to make impossible to miss. It is persistent — no duration — and stays up for as long as either is off.

Theme

One place for every colour, font and border, so panels stay consistent and a retheme is a single-file change. A dark, low-saturation base with a small number of saturated accents reserved for information that changes: health, balance, afflictions.

Colours are given as hex strings for Qt stylesheets and as RGB triples for the echo functions, derived from the same source. Note that Geyser.MiniConsole has no setStyleSheet — that is a Label and Gauge method, and calling it on a console is a hard error. A console's background comes from the color field of its constructor instead.

What the interface costs

Mudlet runs every installed package in one Lua state on the UI thread, so a panel repaint is time the whole client is not drawing, not reading input, and not sending. Two rules, both enforced by the test suite:

  • A panel draws once per repaint, not once per row. The defence grid used to emit a separate Qt rich-text parse per cell — thirty-odd of them.
  • A panel whose rendered content is unchanged does not draw at all. A restock pulling five herbs fires five item events, none of which change what the room shows.
