Getting started

Emunah runs straight from a git checkout. Install it once, switch on the parts you want, and every update after that is one command in the client.

Requirements

  • Mudlet 4.10 or later.
  • An Achaea character, with Achaea's own server-side curing turned off. Emunah does the curing in the client and the two should not compete.
  • git, to clone the repository and to update it.
  • Optional: the MDK package, for tabbed chat. Without it, chat shows in a single window.

Curing, defences and the interface work for any class. Hunting and PvP need a class module to know how to attack, and today that is Priest.

Install

1. Clone the repository

Put it anywhere outside your Mudlet profile directory.

git clone https://github.com/pharanyx-labs/Emunah.git ~/src/Emunah
Do not put the checkout in your profile directory as Emunah

Mudlet's package manager deletes a package's own directory when it uninstalls or reinstalls it, and it follows symlinks. A checkout there, or a symlink to one, would be deleted. If you want the checkout inside the profile anyway, name it EmunahSrc: Emunah looks for that name too, and the package manager never touches it.

2. Install the package

In Mudlet, open Package Manager, choose Install, and select Emunah.xml from the root of the checkout. It is a small loader that runs everything else from the checkout, not the system itself.

Optionally install EmunahTriggers.xml the same way. It adds 659 of the reference system's lines: afflictions gained and cured, stun, prone, sleep and unconsciousness, and its illusion catchers. Emunah applies the reference system's anti-illusion to every one of them. Without it, curing still runs from GMCP, which reports nearly every affliction.

3. Point the loader at the checkout

Run this once in Mudlet's input line. It is saved per profile.

lua EMUNAH_ROOT = "/home/you/src/Emunah"; EmunahBootstrap()

A successful load says:

[emunah] v0.1.0 loaded -- 61 modules.

First steps

Everything is one prefix, emset, and one help command, emhelp.

TypeTo see
emhelpEvery module, what it does, and whether it is on.
emhelp curingOne module: its commands, and every setting with its current value. Click a setting to change it.
emsetStatus: curing, defences, safety floors, and what is being tracked.
emset uiWhether the panels and the map are on.

The command reference lists every command and setting, generated from the same table emhelp reads.

Switching things on

Nothing acts until you turn it on. Curing and defence keep-up are off on a fresh install, and so is everything that moves or attacks.

emset curing on      # cure afflictions and heal
emset defs           # the defence grid: click each to cycle off, defup, keepup
emset defs on        # keep the chosen defences up
emset hunt           # walk the area and bash it (F11); emset hunt off to stop
pp                   # pause or resume curing and defences together

When you want to sleep, type sleep rather than the game's own command: Emunah relaxes insomnia first, and does not wake you or raise insomnia again until you are up.

Settings

Settings are saved per Mudlet profile, in emunah-config.lua in your Mudlet home directory, so two characters keep separate defences, priorities and layouts. Read or change any of them by name:

emset curing.method             # show it
emset curing.method minerals    # change it

The ones most worth reviewing first are the healing thresholds. Each source engages at its own level, and the defaults leave the finite and contested ones for last.

SettingDefaultWhat it does
curing.manaThreshold85%Sip mana below this. Shares the sip balance with health, which goes first.
curing.healthThreshold80%Sip health below this.
curing.iridThreshold68%Eat irid moss below this, for health or mana, on its own balance.
curing.handsThreshold50%Perform Hands below this. It costs equilibrium, which attacking also spends.

When a shipped default turns out to be wrong, a migration corrects the stored value the next time Emunah loads. Your own changes are kept.

Updating

emreload brings the checkout up to date with main on GitHub, then reloads every module from disk without losing state. It only fast-forwards: a checkout on another branch, or one with local edits in the way, is left alone and Emunah says so. emset reload does the same thing, and emreload still works when the command module itself failed to load.

emreload                       # update and reload
emset system.update false      # reload what is on disk, without pulling

Developing

Edit any file under src/ and run emreload. There is nothing to reimport and no client to restart, and a new module added to the manifest is picked up on the same reload.

The suite of 2433 behavioural tests runs the real modules against a simulated Mudlet, with no client involved:

lua5.1 test/run.lua             # the test suite
lua5.1 test/bench.lua           # per-prompt cost, in microseconds and bytes
lua5.1 test/ui_preview.lua      # render the panels in a scripted fight, as HTML

With no Lua installed, python3 tools/run_tests.py . runs the suite through a Python shim.

Troubleshooting

What you seeWhat it means
Cannot find the Emunah source at ...EMUNAH_ROOT is unset or wrong, or the checkout moved. Run step 3 again with the right path.
No class module loaded -- nothing knows how to attack.Hunting and PvP need a class module, and the class is read when you log in. Log the character in first. Priest is the class supported today.
A panel is missing, stuck, or the wrong sizeemset ui rebuild rebuilds every panel from scratch.
Something is not happening and you cannot tell whyemset debug prints every command Emunah sends, and every one it holds back with the reason: stunned, prone, no balance, and so on.
A setting does not seem to take effectemset <setting> with no value reads back what is stored.
