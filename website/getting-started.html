Getting Started

Three steps: clone the repo, import the package into Mudlet, point the bootstrap at your checkout. Nothing gets copied into your Mudlet profile — Emunah runs directly from the git checkout.

Prerequisites

Mudlet installed, a Mudlet profile connected to Achaea, and git available on the command line.

Install

1

Clone the repo somewhere outside your Mudlet profile

git clone <this-repo> ~/src/Emunah
Do not put this inside your profile directory named "Emunah"

Mudlet's package manager deletes a package's own directory on uninstall or reinstall, and it follows symlinks — pointing or symlinking your working checkout there will delete it. If you want the checkout inside the profile directory anyway, name it EmunahSrc instead: the bootstrap looks for that name too, and the package manager never touches it.

2

Import Emunah.xml

In Mudlet: Package Manager → Install, and select Emunah.xml from the repo root. This installs the small bootstrap script that loads everything else from your checkout — it is not the system itself.

3

Point the bootstrap at your checkout

Run this once — Mudlet remembers it per profile:

lua EMUNAH_ROOT = "/home/you/src/Emunah"; EmunahBootstrap()

You should see:

[emunah] v0.1.0 loaded -- 42 modules.

That's it — Emunah is running. Try emunah in Mudlet's command line to see the full command list.

Settings

Settings persist per Mudlet profile in emunah-config.lua (in your Mudlet home directory), so two characters in the same Mudlet installation keep separate priorities, defence lists, and UI layout without any extra work. Read or write any setting directly with emunah set — see the Configuration section of the command reference.

Nothing runs until it is enabled

The curing engine and defence keep-up never auto-enable on a fresh install; they are turned on explicitly with emunah cure on and emunah defs on. The same applies to the walker, hunting and PvP.

Healing thresholds

The settings most worth reviewing are the healing thresholds. Four sources draw on three independent balances, so they overlap rather than compete, and each engages at its own percentage.

SettingDefaultBalance
curing.manaThreshold85%Sip — shared with health, which takes priority
curing.healthThreshold80%Sip
curing.iridThreshold68%Moss
curing.handsThreshold50%Equilibrium
 
emunah set curing.healthThreshold 75

The configuration file carries a schema version. When a shipped default is found to be wrong, a migration corrects the stored value on load — a stored setting otherwise outlives the fix for it, since only absent keys take a new default.

Development loop

Edit any file under src/ in a real text editor, then run emreload in Mudlet. The whole module tree — core, GMCP tracking, curing, UI, walker, everything — is torn down and rebuilt from what's on disk, including a brand-new file you just added to the loader's manifest. No re-importing a package, no restarting Mudlet.

Running the test suite

Emunah ships with 470+ behavioural tests that run the real modules against a Mudlet mock — no live client needed:

# with a Lua interpreter installed:
lua test/run.lua

# or, with none installed, via a Python + lupa shim:
python3 tools/run_tests.py .

Building the distributable package

# Emunah.xml -- no toolchain needed
python3 tools/build-xml.py

# a .mpackage bundle -- needs the muddler build tool and a JVM
cd package && muddle

Troubleshooting

SymptomCause & fix
Cannot find the Emunah source at ... EMUNAH_ROOT is wrong, unset, or the checkout moved. Re-run step 3 with the correct path, or set EMUNAH_ROOT again before emreload.
No class module loaded -- nothing knows how to attack. emunah bash on / emunah hunt / emunah pvp on all refuse to start without a recognised class. Right now that's Priest only — see Class Support. The class is auto-detected from Char.Status once you log in, so this usually means you haven't logged your character in yet this session, or you're playing a class Emunah doesn't have an offence module for.
The map/UI panel is missing or the wrong size emunah ui map with no argument runs a full diagnostic (Geyser present? mapper widget built? map database populated?) rather than toggling anything.
A setting doesn't seem to take effect Check it actually saved: emunah set <key> with no value reads the current value back. Booleans and numbers are coerced automatically; anything else is stored as a string.
Reloading after adding a new file does nothing Use emreload (which re-reads the loader file and its module manifest), not a plain re-require — see the reload model for why this distinction matters.
