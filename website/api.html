Lua API

Everything under the emunah. namespace that is safe to call from your own aliases, triggers and scripts — and, just as importantly, the handful of things you should call instead of the obvious Mudlet equivalent.

Core principle

If you take nothing else from this page: automated commands go through emunah.act.send(), not Mudlet's send().

Achaea refuses commands for reasons that have nothing to do with the command itself — you are stunned, you are lying down, the balance it costs has not come back. send() knows none of that and will happily fire into a rejection, once per prompt, for as long as the condition lasts. act.send() is the single gate that knows the rules.

-- Wrong: fires into "You are too stunned to be able to do anything."
send("smite " .. target)

-- Right: held until the character can actually act
emunah.act.send("smite " .. target, { standing = true, bal = true })

The exception is a command you typed. A keypress or an alias you triggered yourself should go straight out with send() — you asked for it, and second-guessing a human is how a system feels broken. Emunah's own keybindings do exactly this.

emunah.act — command gating

Requirements are a plain table. State what a command costs; the module decides when that is satisfiable.

RequirementMeaning
standing = trueFails while knocked down. Attacks and GET need this; eating a herb and drinking an elixir do not.
bal = trueNeeds balance, from Char.Vitals.
eq = trueNeeds equilibrium.

Stun is deliberately not a requirement you can declare: it blocks literally every command, so it is checked for all of them regardless of what they ask for.

emunah.act.send(command, needs) → boolean

Sends the command if the character can act, and returns whether it actually went. Logs the decision either way under emset debug, so a held command is visible rather than looking like the system hung.

emunah.act.can(needs) → boolean

Asks without sending. Use it to decide whether to bother building a command at all.

emunah.act.blocked(needs) → string|nil

Why not, as a short reason ("stunned", "prone", "no balance", "no equilibrium"), or nil when the command can go. The string is meant for logging — do not branch on its exact wording.

emunah.queue — balance-gated actions

Achaea does not have one queue, it has several independent ones: eating a herb, applying a salve and smoking a pipe consume three different balances and can all be in flight at once. The queue models that as one slot per vector, where a vector is any resource that gates an action.

Each slot holds at most one command. A higher-priority push replaces what is waiting; a lower-priority one is dropped rather than stacked, because a backlog of stale cures is worse than none.

emunah.queue.push(vector, command, opts) → boolean

Queue an action. Returns whether it was accepted (false means something more urgent already held the slot).

  • priority — lower wins, default 100
  • tag — what this is for, e.g. an affliction name; used to match confirmations
  • confirm — seconds to wait for the game to acknowledge before re-arming
  • needs — passed straight to act, e.g. { standing = true }
  • onSent, onTimeout — callbacks
emunah.queue.push("herb", "eat bloodroot", {
  priority = 5,
  tag      = "paralysis",
  confirm  = 2.0,
  onSent   = function() emunah.have.spend("herb") end,
})
CallDoes
queue.flush()Sends whatever is pending on every free vector. Driven once per prompt — you rarely call this yourself.
queue.pending(vector)What is waiting on a vector, or nil.
queue.awaiting(vector)What has been sent but not yet confirmed.
queue.confirm(vector)Mark the in-flight action confirmed, freeing the vector early.
queue.clear(vector)Drop what is pending on one vector, or all of them with no argument.
queue.snapshot()Everything pending and in flight, for inspection.

Vectors: free, balance, equilibrium, herb, salve, elixir, smoke, focus, tree, writhe, special.

emunah.have — capability checks

Answers “can I actually do this?” from tracked GMCP state. Nothing here sends a command or guesses; when the data has not arrived yet the answer is a conservative one.

This exists because of one specific, maddening failure mode: a curing engine that does not check first picks the right cure, sends eat kelp, gets “You do not have that item”, the affliction stays, and it sends the same thing again next tick — forever, while you die.

CallAnswers
have.skill(name)Do I know this ability? Permissive while the skill index is still loading.
have.skillset(name)Do I have a whole skillset? Cheap class inference.
have.item(name)How many are in inventory.
have.inRift(name)How many are in the Rift.
have.supply(name)Inventory plus Rift — usually the one you want.
have.pipe(herb)Is there a lit pipe with this herb in it? Not the same question as “do I have valerian”.
have.def(name)Is this defence up?
have.affliction(name)Am I afflicted with this?
have.balance(vector)Is this vector free right now?
have.blockedBy(vector)Which affliction is blocking this vector, if any.
have.cure(option)Can I perform this cure? Returns false, reason when not.
have.spend(vector) / have.recover(vector)Mark a vector spent or recovered ahead of its timer.
have.denySkill(name)Record that the game itself refused an ability, overriding the index.

emunah.curing.detect — incapacitation state

Two states that are routinely caused by the same hit but clear independently. Prefer letting act consult these for you; read them directly only when you need to branch on why.

CallMeaning
detect.isProne()Knocked down. A STAND is already on its way; nothing else needs to send one.
detect.isStunned()Stunned. Nothing can be sent at all — no command fixes it, it just wears off.
detect.add(aff, kind, pattern)Register a detection pattern. kind is "gain" or "cure".
detect.define(aff, spec)Several patterns at once: { gain = {...}, cure = {...} }.
detect.coverage()How much of the affliction list has patterns.

Both flags gate sending, so a clearing message that never arrives would not degrade the system — it would freeze it. Each therefore has a backstop timer (detect.STUN_GUARD, detect.PRONE_GUARD) that releases the state if the game never says it ended.

emunah.event — events

Handlers registered through this module are tracked so a reload can drop the previous generation. Registering with Mudlet's registerAnonymousEventHandler directly is the classic way to end up eating three bloodroot for one affliction after three reloads.

emunah.event.register(name, fn, owner)

owner is any grouping string. Pass your own and you can drop all of your handlers at once with emunah.event.kill(owner).

emunah.event.register("emunah.bashing.killed", function(_, id, name)
  cecho("\n<green>Killed " .. tostring(name))
end, "myscript")

Every system event is prefixed emunah.. The first argument your handler receives is the event name itself — that is Mudlet's convention, which is why the examples discard it with _.

emunah.timers — named cooldowns

Every balance in Achaea is a cooldown. Some returns are announced by the game and arrive over GMCP; the rest are only observable by timing. This handles the timed kind.

CallDoes
timers.start(name, seconds, onExpire)Start or restart a cooldown.
timers.ready(name)Has it lapsed? The one you usually want.
timers.stop(name)Cancel early — the normal response to the game confirming a balance is back sooner than estimated.
timers.remaining(name)Seconds left, or 0.
timers.progress(name)Fraction elapsed, 0..1. Feeds the UI gauges.

emunah.config — settings

Dotted paths, persisted per profile. Every setting emset reads or writes is reachable here.

emunah.config.get("bashing.attack", "smite")
emunah.config.set("bashing.stopBelowHealth", 60)
emunah.config.save()

Loops: bashing, walker, pvp

Targets are replica numbers, not names. denizens.here() returns ids like 308635 because smite pixie lets Achaea choose which pixie, and its choice shifts as they move and die. Pass the id through to any attack.

Everything the manifest publishes, in load order. The modules above are the ones a third-party script is most likely to build on; these are the rest, and they are reachable the same way.

Two functions worth knowing about

emunah.have.quantity(name) counts a consumable in inventory, memoised against gmcp.items.generation and dropped wholesale whenever anything moves — a stale count is what makes an engine queue a cure it cannot perform.

emunah.ui.theme.paint() is how every panel draws. If you add one, use it: it collapses a body into a single decho and skips the call entirely when nothing changed, which is the difference between a panel that costs nothing and one that costs a frame on every game event.

Example: a script built on Emunah

A worked example that ties the pieces together — drink a health elixir when hurt, without ever fighting the curing engine for the vector or firing into a rejection:

emunah.event.register("emunah.tick", function()
  local v = emunah.gmcp.vitals
  if not v.below("hp", 50) then return end
  if emunah.have.supply("health") == 0 then return end

  emunah.queue.push("elixir", "drink health", {
    priority = 20,
    tag      = "emergency",
    confirm  = 2.0,
    onSent   = function() emunah.have.spend("elixir") end,
  })
end, "myscript")

Note what this does not do: it never calls send(), never checks whether you are stunned, and never worries about sip balance. Pushing onto the elixir vector means the queue holds it until that balance is genuinely free, act holds it further if the character cannot act at all, and a higher-priority cure can pre-empt it if something worse lands in the meantime.

Register with your own owner string and emreload will not leave a duplicate behind.
